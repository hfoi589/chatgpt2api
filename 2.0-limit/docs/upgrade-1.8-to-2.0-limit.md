# 1.8 → 2.0-limit 迁移

## 升级前备份

1. 在 1.8 的「账号」页面选中需要迁移的账号，导出为 JSON。也可以调用 `POST /api/accounts/export`，请求体使用 `{"access_tokens":[...],"format":"json"}`。请保留导出的 `codex-accounts-*.json` 文件；ZIP 格式不用于本流程。
2. 如果尚未做过历史用量回填，先在 1.8 项目目录运行 `python scripts/migrate_user_usage.py`。脚本按 1.8 调用日志回填历史生图用量，并通过版本标记避免重复累计。
3. 备份用户密钥和图片额度。JSON 存储后端通常使用 `data/auth_keys.json`；如果使用其他存储后端，请在 1.8 备份包中启用用户密钥快照，并取出 `snapshots/auth_keys.json`。文件中的 `key_hash` 是不可逆哈希，2.0-limit 会据此让旧客户端密钥继续认证。
4. 停止 1.8 服务，再将以上备份文件保存到安全位置。不要把账号 JSON、密钥快照、`config.json` 或数据库文件放入镜像构建目录。

## 部署 2.0-limit

2.0 使用新的 Go 服务和数据库结构。旧版数据库不能直接挂载为 2.0 数据库；2.0 会在自己的 `data/` 目录创建数据库。保留 1.8 的原始数据目录作为备份，不要用新数据库覆盖它。

从项目根目录构建本地镜像：

```sh
docker build -t chatgpt2api:2.0-limit ./2.0-limit
```

运行时使用 2.0 的 `config.yaml` 和持久化 `data/` 目录，并设置新的管理员密钥。旧 `config.json` 不能直接作为 2.0 配置文件；可将管理员密钥、代理和图片存储设置迁入 2.0 的 YAML 配置。

## 导入账号与用户额度

1. 启动 2.0-limit 后，打开「账号」→「导入」→「账号 JSON 文件」，选择 1.8 导出的 JSON。导入器支持单账号对象或账号数组；确认识别数量后执行导入。
2. 打开「密钥」页面，选择「导入 1.8 额度备份」，再选择 `auth_keys.json` 或 `snapshots/auth_keys.json`。导入会保留用户密钥 ID、哈希、每日/每周/总额度、累计用量、启用状态和时间窗口；已存在的 ID 或哈希会跳过。
3. 旧版只保存密钥哈希，因此迁移后的密钥不会在管理页面显示明文。已有客户端可以继续使用原密钥；如需更换，在密钥编辑页输入新密钥后保存。留空表示不更换。

每日、每周周期沿用 1.8 的 `America/New_York` 时区口径。总额度字段表示剩余张数，图片请求会先预占，成功后按实际返回张数结算，失败会退回预占额度。管理员密钥不受用户额度限制。

## 更新模型名

2.0-limit 默认对外生图模型为 `gpt-image-2.6`，与 2.0 一致。调用方原来传 `gpt-image-2` 的配置需要改为 `gpt-image-2.6`；也可以在 2.0 设置页的「生图模型名称」中配置其他对外名称。Codex 图片工具模型默认同为 `gpt-image-2.6`。

## 迁移范围

本流程迁移账号凭据和用户密钥额度。1.8 的历史日志、对话、图库记录及旧数据库结构不导入；请继续保留旧数据目录供查询。镜像构建上下文已排除 `data/`、配置文件和数据库文件。
